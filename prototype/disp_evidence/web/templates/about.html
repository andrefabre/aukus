How it works

Each month the same pipeline runs inside the client's tenant: collect, seal, analyse, sign off, then produce the pack. Evidence only moves forward through these stages.

1 · CollectRead-only collectors pull Entra ID, Intune / Defender, HR, training, visitor and incident data at month end.
2 · SealEach artifact is SHA-256 hashed. The manifest is signed and chained to the previous month, and files are written once.
3 · AnalyseThe rules engine, or an optional LLM, drafts the control assessment. A deterministic gate rejects invented or over-claimed evidence.
4 · AttestThe Security Officer approves or rejects in a Teams-style card. The decision is signed and appended to that month.
5 · ReportA monthly PDF + JSON evidence pack, the dashboard and the ASR data pack. Exceptions become Planner tasks.

Demo talk track (5 minutes)

  1. Dashboard: six sealed months. Point at the red cells, then hover for the headline.
  2. Open the latest month → JML. The leaver whose account was never disabled is a critical exception, so the Security Officer signs off with comments.
  3. Control analysis: draft an assessment. The gate passes, and the Security Officer approves it and it is sealed. Then run the faulty-llm-demo engine and watch the gate block the invented citation and over-claim.
  4. Evidence pack PDF: show the manifest hash, chain, signature and integrity check that an assessor can rely on.
  5. Vault → Tamper: change "LATE" to "on time" in a sealed JML file. Integrity flips to FAILED, which shows the evidence can't be quietly fixed later. Then restore it.
  6. Run this month's cycle now: a new month is collected, hashed, signed and chained in about a second.
  7. ASR data pack: the year's evidence for the Annual Security Report, already assembled.
